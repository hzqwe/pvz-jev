当前 [向日葵女王页面](https://pvzhe.wiki/w/向日葵女王) 提供 ID 86、500+ 阳光、生命值 1000、追踪攻击及产阳光等信息，但没有完整说明递增价格公式和全部组合条件。这说明“有图鉴页面”不等于“机制已完整覆盖”。当前页面也不天然代表 3.9.9：优先查版本明确的资料、可用历史修订与更新公告，缺少历史证据的字段标为版本未核实。不能假定本站一定提供公开修订 API。

## 数据设计

每条实体按 `(edition='classic', game_version='3.9.9', kind, type_id)` 标识。名称只是 canonical_name 与 aliases。逐字段保存 `value / source_url 或本地证据 / source_revision / applicable_version / confidence / observed_at`；未知值使用 null。

机制分为：价格与冷却、产阳光、投射物与覆盖、平台/主体/外壳层、目标限制、状态效果、铲除回收、车辆接触、跳跃与防具、组合触发条件。保留实际伤害下限/上限与估算命中率的区别，不把散射理论总伤害当单目标必中 DPS。

实时血量、护甲、位置、卡槽冷却和实际价格优先使用已验证读数。实测冲突按版本、难度和关卡记录；一次失败不能污染全局永久基础价格。导入完成后输出覆盖报告：身份覆盖率、各机制字段覆盖率、当前卡组缺失字段、冲突和未核实项，不能只报告条目数。

## 分阶段交付

1. **身份与版本包（先做）**：固定 β0.66，静态提取 ID 表和来源；审计当前 15 张卡及僵尸别名；识别新牌组时区分身份已知与机制已知。详细计划见 `superpowers/plans/2026-09-28-versioned-catalog.md`。
2. **机制补齐与价格校验**：为版本允许的实体收集经典 Wiki/图鉴事实；先修复 ID 0、16 的能力疑点与版本混用；明确价格增加的触发条件及铲除后变化。兼容现有已确认规则，资料矛盾进入待核对清单。
3. **地图与操作泛化**：水生植物、底座、主体和外壳分别处理；泳池和屋顶合法性按能力决定。先底座、再主体，每步用棋盘变化确认；屋顶独立校准坡度坐标和弹道，未验证几何时不盲点。
4. **组合与短期预测**：按投射物类型和路径计算过火收益；按真实射程、穿透、减速、护甲与碾压预测接战。复用当前候选生成和兜底代码，Jev 只比较已经合法且有依据的动作。
5. **对照评估**：保留原 15 卡回归场景，加入未用于调参的卡组、泳池和屋顶场景；比较识别失败、种植成功率、价格错误、失车/败局、经济发展、延迟和真实 API usage。先离线/只读预演，再做小范围实战。

不把整个百科放进每次请求。运行时仅提供所选卡组、当前敌人、地图约束和可实现的组合摘要。百科转换与事实核验发生在离线更新阶段；本地规则负责精确计算，因此扩大知识覆盖不要求每一步增加一次大模型检索。
