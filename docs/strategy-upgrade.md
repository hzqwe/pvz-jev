# 决策优化说明（2026-09-26）

保留现有 Jev API 和游戏点击链路，优化感知、候选、取舍校验；不写游戏内存。
TypeSafe 官方 typesafe-ai 技能已安装到 Codex 用户技能目录。

## 铲子/回收支持（同日第二批）

此前 agent 完全没有铲子动作（回收高坚果的图鉴注释就是 "Agent has no shovel
action"）。本批补齐了完整链路，仍然遵守"每一步都要有内存证据"：

- **感知**：`CursorObject+0x30` 不再只当 0/1 用 —— 它是 `mCursorType` 枚举
  （反编译 ConstEnums.h：0=空手、1=手持种子、6=铲子）。`BoardState.holding_shovel`
  据此判断。植物血量按反编译 Plant.h 读 `+0x40/+0x44`（杂交版沿用原版字段布局，
  P_TYPE/P_COL/P_ASLEEP 均一字不差；读取仍有 0<=hp<=max 边界校验，读不出合法值
  一律 None，绝不拿垃圾值当血量）、`+0xB4` 读"正在被啃"。
- **点击**：铲子按钮在卡条右端，2560x1600 基准下 ≈(2220,95)（两份对局截图的
  金色像素定位），随分辨率缩放；执行链路：点铲子 → **必须读到光标=6** → 点
  目标格 → **必须读到该格空了**，任何一步失败都右键复位光标（防止下一次
  收阳光的点击铲掉无辜植物）。
- **决策**：只有"可回收"的墙（回收高坚果）会生成铲子候选，护栏来自图鉴：
  扣 800 血、血量 >800 才能变回卡片 —— 所以血量未知 / <=800 / >2400 都不铲；
  还要求该路有僵尸且（正在啃它 或 路线告急）。候选理由会向 Jev 说明
  "跌破 800 就永远收不回来"。危急时铲子候选也算救场动作。
- **验证**：39 项单元测试、selftest_policy、selftest_hang 全过；Jev 链路自检
  新增第四个真实请求场景 reclaim_shovel（1000 血、正在被啃、卡槽为空），
  模型自主选择 `shovel:Recyclable Tall-nut`、无兜底。
- **边界**：植物血量偏移在杂交版还没在对局里现场核验过（当前游戏未运行）；
  若实际偏移不同，血量读取会返回 None，铲子候选自动缺席 —— 失败方向是
  "不铲"，不是"乱铲"。铲其他植物（腾格子/换阵容）仍不支持，属刻意收窄。

## 图鉴能力接入决策层（同日续作）

15 张图鉴照片的结构化 combat 字段此前只是"给 Jev 看的说明"，现在也进入
代码自己的确定性评分（评分是启发式权重，不是宣称实测 DPS）：

- **反伤**（雷果子 80/s、冰冻坚果 20/s）：`lane_facts` 新增 `reflect_support`。
  只在僵尸真的啃到墙（最近僵尸 x ≤ 墙列 x + 30）时计入，且只扣减 pressure、
  不抬高"high"威胁阈值 —— 反伤不是主动火力。
- **灼烧光环**（向日葵女王 40/s）：只统计与落点同行/邻排、还在光环射程内
  的僵尸，不当全屏伤害计分。
- **阳光转化**：阳光炸弹按命中数给小额评分加成（图鉴未给返还数值，事实层
  不编造数字）；寒光菇按"每冻结一个僵尸最多 15 阳光"加成，并注明免疫目标
  不保证。
- **亡语冻结**（冰冻坚果/高冰果）：落点评分 +6，候选理由向 Jev 说明
  "倒下时仍有死亡涟漪"。
- **可回收墙**（回收高坚果）：评分 +4 并注明"铲除动作尚未实现，回收只是潜力"。
- **成长产能**（阳光向日葵）：成熟期收入按 0.15 折算计入，因为生长年龄无法
  观测，不当成确定收入。

新增 7 项回归测试（tools/test_plant_knowledge.py）：34 项单元测试、
selftest_policy、selftest_hang 全部通过；三组真实 Jev 请求通过且不再兜底。

## 行为变化

- 向日葵和普通射手只能选择墙后、僵尸尚未走过的空格；后排满了不会向墙前溢出。
- 冰冻坚果等复合植物优先考虑拦截位置，不再因为射手标签而跳过墙的逻辑；
  若已有墙、火力不足，也可在墙后提供射击支援。
- 各路威胁综合近屋距离、敌人数量、观测血量与护甲、可用射手和墙、小推车状态。
  无车且有攻击压力的路线得到加权；空的无车路线不会抢走别路的救场资源。
- 建立至少四株经济植物且防线不告急时，为可放置的强力持续火力建立预算。
  攒钱期间便宜植物也不能随意透支目标；局势告急就解除预算。
  阳光足够且目标卡就绪后兑现升级，避免模型无限等待。
- 危急时只要有可用救场候选，就不接受模型的等待或无关种植。
  全屏救场允许用于单只近屋僵尸；局部炸弹按实际几何范围统计命中目标。
- 同格的不同植物仍可竞争，不再因为按位置去重而删除有效选项。
- Jev 得到僵尸原始类型编号、血量和护甲，不再把僵尸误叫成植物。
  受魅惑的友方僵尸不计入敌方压力。
- 点击前再次核对关卡、进程、卡槽类型、冷却、阳光、占位和战术可用性。
  动作已过期则放弃，下一轮重新决策。保留既有暂停/卡死保护。

## 观测边界

- 本次游戏处于选卡界面。只读核对了僵尸身体/护甲数值，未接管或完成一整局，
  因此不能据此宣称胜率提升多少。
- 小推车采用既有数组布局，并增加对象反指针、状态、数量一致性检查。
  未生成、布局不符或读取不全时返回未知，不把读取失败误认成丢车。
  **杂交版真实对局中的小推车状态仍需核对**；未知状态不会被当成“有车保底”。
- 压力和防守能力是启发式估计，价格仅作火力等级的粗略参考，不是实测 DPS、
  精确击杀时间或保证获胜。未知僵尸类型不猜名字；无血量数据时保守使用默认强度。
- 水面平台、屋顶花盆、特殊僵尸移动方式及植物特殊进化仍沿用原项目限制。

TypeSafe 的问题设计参考官方 [Choice](https://docs.typesafe.ai/primitives/choice) 和
[并行问题模式](https://docs.typesafe.ai/patterns/fan-out)：各问题独立判断，代码合并结果。
新增内存字段参考 [Zombie.h](https://github.com/ruslan831/PlantsVsZombies-decompilation/blob/master/Lawn/Zombie.h)
和 [LawnMower.h](https://github.com/ruslan831/PlantsVsZombies-decompilation/blob/master/Lawn/LawnMower.h)，
原版结构只是候选依据，不能替代杂交版运行时校验。

## 2026-09-26：空窗期建设与开局储蓄修正

复核日志：`decisions_20260926_131203.jsonl` 共 132 轮，24 次执行 hold 时阳光至少 800，包括 1245 阳光、无僵尸；14:22 日志共 100 轮，出现 865 阳光、无僵尸的 hold。高阳光等待不都错误，但无威胁且阵型缺位时应主动建设。

本轮规则：
- 现有危急救场优先级保持；无高危路线、阳光至少 1000 时，也允许给无僵尸的空路补持续火力。
- 模型要求等待时，重新检查当前合法候选。只补缺少的经济/射手/墙；一般保留 300 阳光，前 4 株经济植物保留 100。阵型已满足、卡在冷却或正在储蓄时仍可等待。
- 平静期用比例降低分数，保留不同植物的能力差异，避免所有贵卡廉价卡被截成同分。
- 普通向日葵按安全空格的列优先填充。女王开局储蓄只在无僵尸、卡就绪、B/C 有位置、距实际价格不超过 100 阳光时启用；出现敌人重新评估，攒够即兑现。沿用真实价格，不能将当前 600 的卡强行按图鉴 500 购买。
- 女王后方豌豆、雷果子前排墙系、贴身重叠拦截沿用现有逻辑；贴近脆弱植物的墙允许释放早期经济储备。
- 垫背落点修正为按 80px 格子中心选取。非濒死救场的垫背需要后方火力及预计可获益的攻击窗口，且垫背必须在被保护射手前方。估算采用 8px/s 行走、每只近邻僵尸 100hp/s 啃食，明确属于假设，尚无实测速度/命中时间。近屋绝境仍保留最后一次延迟机会，不宣称一定等到墙冷却。

验证：59 项 unittest 通过；离线策略场景、防卡死自测通过。真实 Jev smoke test 在第一个请求收到 `HTTP 403: RBAC: access denied`，因此没有在线推断通过或实战胜率提升的结论。未修改凭据，未自动操控游戏。代码审查发现的女王储蓄无可用落点、垫背在射手身后两个问题已加入回归测试并修复。
