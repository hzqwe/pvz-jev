# 决策优化说明（2026-09-26）

保留现有 Jev API 和游戏点击链路，优化感知、候选、取舍校验；不写游戏内存。
TypeSafe 官方 typesafe-ai 技能已安装到 Codex 用户技能目录。

## 行为变化

- 向日葵和普通射手只能选择墙后、僵尸尚未走过的空格；后排满了不会向墙前溢出。
- 冰冻坚果等复合植物优先考虑拦截位置，不再因为射手标签而跳过墙的逻辑；
  若已有墙、火力不足，也可在墙后提供射击支援。
- 各路威胁综合近屋距离、敌人数量、观测血量与护甲、可用射手和墙、小推车状态。
  无车且有攻击压力的路线得到加权；空的无车路线不会抢走别路的救场资源。
- 建立至少四株经济植物且防线不告急时，为可放置的强力持续火力建立预算。
  攒钱期间便宜植物也不能随意透支目标；局势告急就解除预算。
  阳光足够且目标卡就绪后兑现升级，避免模型无限等待。
- 危急时只要有可用救场候选，就不接受模型的等待或无关种植。
  全屏救场允许用于单只近屋僵尸；局部炸弹按实际几何范围统计命中目标。
- 同格的不同植物仍可竞争，不再因为按位置去重而删除有效选项。
- Jev 得到僵尸原始类型编号、血量和护甲，不再把僵尸误叫成植物。
  受魅惑的友方僵尸不计入敌方压力。
- 点击前再次核对关卡、进程、卡槽类型、冷却、阳光、占位和战术可用性。
  动作已过期则放弃，下一轮重新决策。保留既有暂停/卡死保护。

## 验证

在项目根目录执行（Windows 上可使用现有 Python 3.13.12 的绝对路径）：

```powershell
python -m unittest discover -s tools -p 'test_*.py'
python tools/selftest_policy.py
python tools/selftest_hang.py
python tools/selftest_strategy_jev.py
```

最后一条需要已配置的 TypeSafe API 密钥，会产生三次合成战场 API 请求，不操作游戏。
结果写入 `out/strategy-validation.json`，含模型原始回答、最终动作和是否发生兜底。
本次验证：20 项策略/读取/执行测试通过，原有六组候选展示和防卡死测试运行通过。
三组真实 Jev 请求（jev-1.13.0）分别验证等待储备、近屋救急、兑现升级；
本次“兑现升级”使用了确定性兜底，不能把它说成模型独立做对了判断。

## 观测边界

- 本次游戏处于选卡界面。只读核对了僵尸身体/护甲数值，未接管或完成一整局，
  因此不能据此宣称胜率提升多少。
- 小推车采用既有数组布局，并增加对象反指针、状态、数量一致性检查。
  未生成、布局不符或读取不全时返回未知，不把读取失败误认成丢车。
  **杂交版真实对局中的小推车状态仍需核对**；未知状态不会被当成“有车保底”。
- 压力和防守能力是启发式估计，价格仅作火力等级的粗略参考，不是实测 DPS、
  精确击杀时间或保证获胜。未知僵尸类型不猜名字；无血量数据时保守使用默认强度。
- 水面平台、屋顶花盆、特殊僵尸移动方式及植物特殊进化仍沿用原项目限制。

TypeSafe 的问题设计参考官方 [Choice](https://docs.typesafe.ai/primitives/choice) 和
[并行问题模式](https://docs.typesafe.ai/patterns/fan-out)：各问题独立判断，代码合并结果。
新增内存字段参考 [Zombie.h](https://github.com/ruslan831/PlantsVsZombies-decompilation/blob/master/Lawn/Zombie.h)
和 [LawnMower.h](https://github.com/ruslan831/PlantsVsZombies-decompilation/blob/master/Lawn/LawnMower.h)，
原版结构只是候选依据，不能替代杂交版运行时校验。
