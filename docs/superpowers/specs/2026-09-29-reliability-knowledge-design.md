# Jev 运行可靠性与领域知识扩展设计

用户已确认上一轮审查建议，并要求实施、增加植物配合/场景/僵尸知识。本设计具体化该范围；不训练 Jev，不改变只读游戏内存的约定，不自动启动游戏或付费实战。

## 目标与边界

1. 同一游戏只有一个输入控制者，避免重复启动及价格观测污染。
2. 知识重载采用完整有效快照：名字、ID、版本补丁、教条、场上对象与卡组绑定同步刷新；失败保留旧快照。
3. 新植物的范围、耐久、触发型经济、地形、支撑层通过统一字段进入规则；仅名称不能冒充机制。
4. 增加有来源的经典版植物/僵尸机制和可执行的配合关系；仅向 Jev 提供当前卡组与当前敌人的相关摘要。
5. 修复多层格子升级、屋顶校准熔断、旧日志兼容；小推车未知的原因应可诊断。
6. 视觉为后续补盲通道：Jev 只接受文本。当前实现提供内存缺失诊断和离线知识检查，不新增每轮视觉模型调用，也不安装未确定的视觉服务。

## 设计

沿用 Python 标准库和现有模块，避免额外运行依赖。Windows 系统互斥量持有游戏控制权；只读运行不持有输入权。成本观测与确定成本分开，已知基价/递增规律不会被净差额随意覆盖。

PlantBook 构建完整候选快照，解析版本知识后重绑旧绑定和当前牌组；校验成功才交换。知识哈希、代码提交、控制 PID、游戏 PID、动作 ID 进入日志。低可信度占位标签/文本不能覆盖更明确的机制。规范化 `combat.hp` 和 `pierce` 等历史字段。

新增 `data/versions/classic-3.9.9/encyclopedia.json`，结构为 `schema_version=1, edition, game_version, identity_source_revision, plants, zombies, relations, scenes, sources`。

- plants 用 ID 字符串索引，每项 `{canonical_name, profile}`；profile 使用现有 KBEntry 的 `en,cost,hp,cooldown_s,role,tags,combat,effect_en,usage_en,field_sources`，可加 `placement`。字段逐项来源，不覆盖用户已确认事实。
- zombies 用 ID 索引，每项 `{canonical_name, traits, field_sources}`，不猜真实 HP/速度；实际读数优先。未确认碾压不能标为 confirmed。
- relations 为 `{id, kind, plant_ids, reason_en, conditions, source_url, confidence}` 的列表。支持过火路径、墙后射击、控制配合穿透、地图支撑和针对敌人等关系。只筛选当前可用植物相关关系，最多 8 条摘要。
- scenes 为场景 ID 的资料，未知特殊场景保持未知；屋顶/水路能力使用显式 placement 支撑与地形字段，不再仅按中文名字推断。

来源固定 GitHub β0.66 对应 3.9.9 的身份表；社区 Wiki 的当前资料必须标记版本核对状态，不能声称所有数值已在 3.9.9 实测。不执行上游修改器。不按植物名字自动推断攻击/经济/敌人技能。

攻击覆盖支持相邻行与穿透，分开总输出和单行输出。经济分开 battle_sun、currency、sky_amplifier、one_shot 和 contact_trigger；未知收入不满足稳定阳光产能需求。平台通过 placement.support_kind / terrain / layer 表达，兼容已确认旧平台。

多层升级只选上层植物，禁止误选平台；替换前后校验支撑与目标卡，不能依赖之后一轮自动补。屋顶校准使用有限的反向位移，仅从可靠同排错列观察更新；校准成功不立即重新熔断，不把列坡度问题伪装成完整几何模型。

## 验收

- 重复启动不能同时输入，锁随退出释放；只读运行可并行。
- 已知 50 阳光卡不会被 238 的净扣款覆写；动态价格归一化正确。
- 重载能更新已绑定 ID，坏文件不造成半新半旧；教条缓存和覆盖事件更新。
- 当前版本最终财神/招财猫档案具有正确攻击标签；西瓜坚果统一耐久为 4000；三行植物有邻行支援且不重复总预算。
- 货币不计稳定阳光；天降增强不虚记夜间固定收入；平台兼容已确认泳池/屋顶流程。
- 睡莲上升级选上层；小推车校验失败有原因，未知不当成失车。
- 所有新增资料可追溯并区分身份/机制覆盖；当前牌组关系摘要有上限，扩大百科不线性扩大每次请求。
- 全量离线测试、昨日日志回放和独立审查；记录未覆盖的实战限制。
