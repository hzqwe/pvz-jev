## 方案

1. 在现有版本目录添加 `mechanics.json`，以真实 ID、canonical_name、已有 profile_name 和逐字段来源限定补丁。`PlantBook` 在已验证版本下产生独立 KBEntry，退出时恢复原档案。原用户名字和成本缓存保留，不全局修改旧档案或同名不同 ID。
2. 本地通用函数依据位置、射程和投射物能力判断可命中目标。普通前向射手打不到身后的最近敌人，短射程也不能计作远处敌人的防御；追踪保持全局分摊。穿透的群体贡献按实际可命中同行敌人计算。女王路径只对同行、位于射手和目标之间且醒着的火炬成立；未核实伤害倍数不参与救命时间保证，只作候选配合收益。
3. 向 Jev 提供紧凑的产能摘要和候选配合理由；不增加 API 次数，不发送整个资料包。已有低威胁、富阳光补阵型规则在生成和合并侧保持一致，不能因为还有普通远僵尸就一直等待。
4. 只读审计统一现有/版本可绑定档案，区分 bound/available，输出推定字段和来源冲突。审计不得更改绑定、成本或 TTL。

不改点击、回收事务、地图坐标、API 接口、冷却或价格公式。暂不补造睡莲攻击数值、女王增伤倍数、任意僵尸技能或屋顶操作。
